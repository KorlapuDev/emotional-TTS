# Emotion-Aware TTS Pipeline

An advanced, emotion-aware Text-to-Speech (TTS) pipeline designed to take raw narration scripts (including Romanized Hinglish) and generate high-fidelity, expressive, zero-shot cloned voiceovers using Local AI.

## Architecture

This pipeline is broken into two intelligent phases:

### Phase 1: Script Analysis & Processing (`analyzer.py`)
Powered by a local LLM via **Ollama** (e.g., `llama3.2:3b`), this module processes the raw text to:
1. **Chunking**: Splits long sentences into strict 8-12 word bursts to prevent XTTS character-limit overflow and audio degradation.
2. **Emotion Tagging**: Detects and assigns emotional tones (e.g., *tense, nostalgic, dramatic, calm*).
3. **Pacing & Pauses**: Assigns dynamic speed multipliers (0.85x to 1.10x) and realistic pause durations between chunks.
4. **Devanagari Transliteration**: Automatically converts Romanized Hinglish (e.g., "kaam") into pure Devanagari script ("काम"). This is crucial because passing Roman characters into XTTS with a Hindi language tag causes heavy, unnatural foreign accents.

### Phase 2: Speech Synthesis & Assembly (`synthesizer.py`)
Powered by **Coqui-TTS** (specifically the `XTTS_v2` model), this module:
1. Performs zero-shot voice cloning using a 6-10 second clean reference audio file (`reference_voice_clean.wav`).
2. Iterates through the JSON chunks generated by the LLM and synthesizes them individually.
3. **Stitching**: Uses `pydub` to seamlessly blend the generated chunks together with 30ms crossfades, preventing audio clicks and pops.

### Orchestration (`main.py`)
The main entry point that ties the LLM and TTS engines together, handles CLI arguments, and dynamically resolves complex Windows DLL dependencies for audio processing.

## Setup & Requirements

### Prerequisites
- Python 3.12 (via virtual environment)
- **Ollama** installed locally with the `llama3.2:3b` model pulled (`ollama run llama3.2:3b`).
- **FFmpeg Shared Build** installed (via winget: `winget install --id Gyan.FFmpeg.Shared -e`).

### Installation
1. Activate your virtual environment: `.\.venv\Scripts\Activate.ps1`
2. Install the necessary packages via `pip` (including `coqui-tts[codec]`).

---

## Usage

Place your source text file (e.g., `sample_script.txt`) and a high-quality, clean, 6-10 second reference voice audio (`reference_voice_clean.wav`) in the root directory.

Run the pipeline:
```powershell
python main.py --script sample_script.txt --reference reference_voice_clean.wav
```

## Technical Hurdles Solved (Developer Notes)

During the development of this pipeline, several complex environment and library integration bugs were encountered and manually patched in the `.venv`:

1. **PyTorch/Transformers Version Conflicts (`coqui-tts` vs newer `transformers`)**:
   - *Issue:* `ImportError: cannot import name 'isin_mps_friendly'` in Tortoise layer.
   - *Fix:* Manually patched `TTS/tts/layers/tortoise/autoregressive.py` to use native `torch.isin`.
   - *Issue:* `AttributeError: 'NoneType' object has no attribute 'shape'` in GPT Inference. Newer HuggingFace libraries omit `attention_mask` (passing `None`), causing XTTS to crash.
   - *Fix:* Rewrote the sequence length calculation in `TTS/tts/layers/xtts/gpt_inference.py` to dynamically infer length from `past_key_values` instead of relying on `attention_mask`.

2. **TorchCodec FFmpeg DLL Loading on Windows**:
   - *Issue:* `torchcodec` failed to load audio decoders because it couldn't find `avformat-*.dll`, even when installed via `winget`. Windows app-execution aliases mask the DLLs.
   - *Fix:* Injected a dynamic path resolver in `main.py` using `os.add_dll_directory()` targeting the exact `winget` installation folder.

3. **XTTS Hindi Number Pronunciation Crash**:
   - *Issue:* When XTTS encounters digits (e.g., "2"), it attempts to convert them to words using the `num2words` library. However, `num2words` raises a `NotImplementedError` for Hindi (`lang="hi"`).
   - *Fix:* Wrapped the internal `_expand_number` and `_expand_ordinal` functions inside `TTS/tts/layers/xtts/tokenizer.py` in a `try/except` block to gracefully fallback to English (`lang="en"`).

4. **Audio Quality / Crackling Fixes**:
   - *Issue:* Hissing, popping, and robotic static in the final stitched audio.
   - *Fixes:* 
     - Dropped naive DB normalization which artificially amplified background noise floors.
     - Implemented 30ms audio crossfades during chunk assembly.
     - Constrained the LLM to output chunks no larger than 12 words, preventing XTTS from overflowing its internal context limit.

5. **Unicode Console Printing**:
   - *Issue:* Printing Devanagari script to the Windows PowerShell (`cp1252`) crashed the pipeline.
   - *Fix:* Safely encoded terminal output in `main.py` and `synthesizer.py` using `.encode(sys.stdout.encoding, errors='replace')`.
